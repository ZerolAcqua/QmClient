# 好友上线与本服进服通知

## 行为边界

- 首次启用、自己重新进服/换图、好友名单或匹配规则变化时静默建立基线。
- 本服通知在主号/分身切换、有效本地玩家信息尚未就绪时重新建立基线，并清除待发问候。
- 已在服玩家改名、改战队、成为好友不触发本服通知；自己的主号和分身不触发。
- 本服通知与自动问候共用进入判断；通知文案和问候延迟不变。

## Review 与修复依据

旧本服逻辑每 0.2 秒只比较槽位 active。`CGameClient::OnNewSnapshot()` 会在缺少 PLAYERINFO 时清空玩家，切换分身又会读取另一份连接快照，暂缺恢复因此会被误判为新进入。

旧上线逻辑每秒扫描同一个 HTTP 缓存，并在 10 秒未见时删除好友。默认 HTTP 刷新间隔为 30 秒，一次漏人的结果就足以让好友被遗忘；32 个服务器一批的分帧扫描还可能跨过名单整体替换，跳过持续在线的好友。

本服逻辑改为跟踪槽位和身份，从首次观察到缺席开始保留 3 秒状态。在线提示只消费本功能主动发起并成功完成的 HTTP 刷新，同帧完整收集后统一比较。连续两个独立刷新结果都确认好友不在原服务器中，才允许后续重新上线提示；服务器缺失或玩家资料不全不能确认离线。首次可靠观察到一个服务器时，其已有玩家静默纳入基线。

同名玩家在 HTTP 名单中改变战队后仍保留观察状态，只有当前符合好友规则的新上线玩家会提示。好友名称集合用于扫描筛选，避免对名单中的每个玩家线性遍历整个好友表。

## 边界与取舍

- 3 秒内的真实离开再进入会静默；同槽位没有被观察到缺席的新人无法与改名可靠区分。
- HTTP 名单没有稳定玩家 ID，无法可靠区分“改为另一个好友名字”和“该好友新上线”；不猜测身份关联。
- 手动刷新发现的上线变化最迟在通知功能的下个刷新周期处理。扫描在一次刷新完成后执行，不再每秒重复扫描旧缓存。
- 首次看到新服务器、切换视角或重建基线期间发生的真实上线可能静默，以避免把已有玩家误报为新进入。
