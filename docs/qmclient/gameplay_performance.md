## 主线程尖峰第三轮（3.4.4）

用户明确允许音乐进程检测在后台执行，音乐来源在检测完成后下一次主线程更新时切换；其它画面、玩法和消息应用时序边界不变。

### 实现

- Windows 音乐进程枚举进入现有 `IJob` 任务池，主线程只检查 `STATE_DONE` 并取结果；仍以两秒为调度间隔。已有任务未完成时不再排入新扫描，不等待、不补排积压轮次。慢任务完成后的下一次主线程更新应用音乐来源；正常未积压时不会额外再等两秒。
- 检测任务只持有扫描函数和位掩码，不捕获组件或引擎对象，worker 只读取音乐注册表的静态进程名，不读取或写入 Hook 配置。配置切换仍在主线程。组件退出只释放引用，任务池保留自己的任务引用；不新增组件退出等待。
- WebSocket 称号消息保留首次解析的 JSON 负载，支持 `data` 内和顶层两种形式。共享所有权负责释放完整根对象，应用名单不再复制原始正文或再次解析 JSON。
- 移除从未读取的 `m_QmRealtimeLastEventType` 字段和对应消息回调，该回调原先只为写入该字段额外完整解析一次消息。因此称号消息从三次 JSON 解析降为一次，其它消息从两次降为一次。游戏数据仍在原主线程队列中按原顺序应用；未改变 WebSocket 协议、消息预算或队列行为。

### 审查发现与修正

1. `ConvertToRgba` 返回“原来是否已经是 RGBA”，不是成功标记。改为转换后检查图像格式，避免误丢弃成功转换的 RGB 图片。
2. 歌词必须先更新目标身份再处理完成结果；同时增加独立 epoch，拒绝重置后同歌同路径的旧任务。移除 `const` 结果造成的歌词容器复制，成功取结果后不再重复派发。
3. Spotify 必须区分原始文本变化与归一化结果变化，保持原配置重置条件。
4. 积分测试不能依赖未链接进 testrunner 的组件实现。改为生产与测试共用 inline 提取函数；所有后台结果均以 `STATE_DONE` 为发布点。

完成上述修正后的只读审查未发现遗留问题。后台任务不捕获组件引用；图像上传仍在主线程。聊天写入队列只在短暂取放任务时加锁，异步写入期间不会持锁阻塞收消息线程。
