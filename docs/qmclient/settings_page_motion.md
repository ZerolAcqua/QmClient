## 性能路径修复（2026-09-14，3.6.1）

用户继续指出性能问题。本次沿用已确认的新设置 UI 范围，补齐实际文字缓存路径。

### 证据与原因

- 只读抽样已有 `qm_perf_2026-09-14_22-12-08.log`，样本时间约为 22:41:51–22:43:56。代表帧记录了 51 个静态文字候选、0 次可直接绘制的容器命中、39 次即时绘制回退、6 次构建排队。它说明存在持续缓存未就绪现象，不能单凭该记录确定全部帧耗时归因。
- `MenuTextElement` 在可见页缺少缓存条目时直接返回共用 fallback，不登记条目，因此未被预热覆盖的普通文字不能靠后续显示建立缓存。设置预热默认关闭。
- `ResetSettingsFrameBudgetForFrame` 每帧清空文字调度预算；普通设置页没有补充该预算的调用。队列出队依赖正余额，因此此前标题优化同样可能一直无法完成容器构建。

### 实现与边界

- 新版设置的共用文字路径允许缓存未命中及失效条目按需登记。卡片标题、复选框文字、普通标签和现有稳定 ID 的设置按钮复用同一条路径。
- 有构建请求且本帧尚未初始化调度预算时，帧末根据实际帧耗时、滚动状态、待处理数和窗口状态取得新预算。本帧已经取得或消耗的预算不会由这条补充路径重新发放。
- 帧末队列另有限额，最多构建 8 个文字容器；滚动及帧压力继续受已有自适应预算约束。语言页收集请求时消耗的预热额度与实际构建额度分开，避免同一请求重复扣减而饿死。
- 队列改为双端队列，出队不用移动剩余全部请求。延迟构建保存原来的字体预设、渲染标志和读取游标，执行后恢复渲染状态。
- 缓存未就绪时显示当前文字；语言、字体失效时取消旧请求，避免旧内容在帧末被重新标为有效。已就绪的文字直接复用容器，动画位移和颜色继续不参与重建判断。
- 旧 UI 的可见条目准入和即时回退策略保持原有分支。没有调整 FPS 上限、渲染后端或玩法。
