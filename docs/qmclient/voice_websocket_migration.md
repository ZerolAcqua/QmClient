# 语音音频迁移到 WebSocket

## 已确认范围

2026-09-17 用户确认：音频使用独立 WebSocket 连接，默认 `wss://qmclient.icu/ws/voice`，支持自定义 `ws://` 与 `wss://` 地址；客户端和服务端均移除 UDP 音频，不提供 UDP 回退或旧版互通。本次只修改源码并补测试代码，不包含部署、编译或执行测试。

保留 Opus 编码、RV01 包布局及协议版本、房间、按键发言、可选语音激活、距离和本地/服务端回环语义。客户端运行链路移除高级 DSP 和按名字名单过滤；旧配置字段保留读取兼容但不再参与处理。在线识别继续使用原中心 WS 和内部 `/qm/realtime` 通道。

## 实现约定

- `qm_voice_server` 接受完整 WS/WSS URL。空值和旧官方默认 `42.194.185.210:9987` 自动使用新官方 WSS 地址；自建服务的旧 `host:port` 配置需要改为完整 URL。
- 每条 WebSocket 二进制消息承载一个原 RV01 包（包头与 Opus 内容），语音包最大 1200 字节；不要求 WebSocket 子协议，不增加包字段。
- 客户端复用现有 WS/WSS 传输及证书校验、自动重连。断线、换服务地址、换游戏服务器、换房间或语音协议版本时清理会话状态，重新连接后重新加入房间；断线采集的音频不补发。
- 本地测试不连接语音服务。关闭语音、离开游戏服务器或按设置失焦暂停时退出音频连接；音频输出设备不可用时仍消费网络消息和保活响应。
- 服务端在原 TCP 9987 上提供 `/ws/voice`，保留健康检查与内部 `/qm/realtime`。连接按原 `version/context_hash/token_hash` 匹配房间，保留 Ping/Pong 和 loopback；断开立即移除成员。
- 客户端语音发送队列限制为 8 包；服务端每连接的待发送队列也限制为 8 包，写入等待上限 1 秒，慢连接退出房间，不阻塞其他接收方。
- Nginx 示例的 `/ws/voice` 直接代理到 `127.0.0.1:9987`，由现有域名虚拟主机提供 TLS。
